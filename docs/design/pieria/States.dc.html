Configuration UI — states

Every state the two configuration screens can be in. Field rows are the whole vocabulary: one row shape, four provenance states, six control kinds.

Six weights only mean anything relative to each other. The bar is the value; the numbers are the detail.

The graph channel weight is 0, so the channel is disabled and its traversal settings are inactive.

Zero is a documented disable, not a small number. The segment disappears and the dependent section greys out.

5 · Save bar

Dirty. The bar does not exist until something changes.

Global page, restart-tier change. The bar says so before you commit, not after.

4 changes PUT /v1/profiles/pieria/config Fix the highlighted field first

Blocked. The daemon rejects the whole payload if one value fails to bind, so the client refuses to send it.

6 · Validation

from .pieria/config.toml
rejected
400 unknown or non-overridable config key: retrieval.embedding-dimension — this key is process-global and cannot be set per profile.

Two sources of truth. The first is caught in the browser; the second is the daemon's own whitelist rejection, surfaced on the offending row rather than as a toast that scrolls away.

7 · Unlocking a locked field

These cannot be changed in place. The embedding dimension fixes the width of the memories_vec column, so changing it invalidates every stored vector — it needs a re-embed, not a save.

Unlock anyway? You will still have to re-embed 2,436 memories.
Unlocked. Saving these needs a restart and a full re-embed.

The daemon has no endpoint that stops this, so the UI is the only guard. Three deliberate steps, and the consequence is stated in memories — a number the operator recognises — not in abstract terms.

8 · Edge states

No overrides

Every field inherits. The summary strip reads 0 of 28 and the reset button is absent — there is nothing to reset.

Daemon unreachable

The form renders from the last known effective config, read-only, with the save bar suppressed. Editing a config you cannot write is worse than not showing it.

Config pushed by CLI

A pieria config sync replaced the overrides while the page was open. The banner offers to reload rather than silently overwriting on save.
