# Phase 6 - Server Mode

## Objective

Add opt-in multi-user server mode with a PostgreSQL storage backend while preserving local SQLite as the default. Server
mode should reuse the same API, ingestion pipeline, retrieval pipeline, and `MemoryStore` contract wherever practical.

## Scope

- PostgreSQL backend with JSONB, generated full-text search columns, pgvector, indexes, and migrations.
- API authentication and profile isolation.
- Local NDJSON export import into server storage.
- No change to local mode defaults.

## Implementation Sequence

1. Finalize the `MemoryStore` seam for multiple backends.
  - Audit all Phase 1-5 storage calls for SQLite-specific assumptions.
  - Move backend-specific SQL and vector details behind implementation classes.
  - Add configuration to select `sqlite` or `postgres`.
  - Ensure local mode remains the default when no server configuration is present.

2. Add PostgreSQL dependencies and configuration.
  - Configure datasource properties for server mode.
  - Add pgvector support.
  - Keep Flyway migration locations separate by backend where needed.
  - Require explicit server-mode opt-in to avoid surprising local users.

3. Implement Postgres schema migrations.
  - Use native UUID or byte/text IDs consistently with the Java domain model.
  - Use `JSONB` for memory payload.
  - Use `TIMESTAMPTZ` for timestamps.
  - Add generated `tsvector` columns for memory and message FTS.
  - Add GIN indexes for FTS and JSONB fields that are queried.
  - Add pgvector `VECTOR(n)` column and HNSW index with cosine operations.
  - Add partial indexes for active non-superseded memories.

4. Implement `PostgresMemoryStore`.
  - Profile resolution and creation.
  - Message insert-or-ignore for idempotent ingest.
  - Memory insert, list, forget, export, and import.
  - Supersession in one transaction.
  - Vector upsert/delete and vector search.
  - FTS search over memories and raw messages.
  - Exact topic key lookup.

5. Add server-mode retrieval parity.
  - Reuse query analysis, RRF, temporal extraction, and synthesis.
  - Map FTS and vector channel queries to Postgres primitives.
  - Keep scoring output comparable with SQLite fixtures where possible.
  - Add backend-agnostic retrieval contract tests that run against both stores.

6. Add authentication.
  - Require auth only in server mode by default.
  - Start with API token or bearer-token authentication unless a richer identity provider is required.
  - Never enable unauthenticated public binding by default.
  - Add clear errors for missing, invalid, and unauthorized credentials.

7. Enforce profile isolation.
  - Prefer Postgres Row-Level Security keyed on a session-scoped `profile_id`.
  - Set the scoped profile before every transaction or request-level storage operation.
  - Add tests proving one authenticated context cannot read, recall, list, export, forget, or supersede another
    profile's data.
  - If RLS is not viable for a specific operation, document and test the equivalent enforcement.

8. Implement import from local export.
  - Accept the NDJSON export generated by local mode.
  - Validate profile target, memory IDs, payload schema, timestamps, and provenance.
  - Insert messages and memories idempotently.
  - Re-enqueue vector-eligible memories for server-side embedding.
  - Report imported, skipped, failed, and queued counts.

9. Add server operations docs.
  - Required Postgres version and extensions.
  - Environment variables and configuration properties.
  - Migration and startup sequence.
  - Auth setup.
  - Import workflow from local SQLite export.
  - Backup and restore notes.

## Tests

- Testcontainers tests for Postgres migrations and extension availability.
- Storage contract tests shared across SQLite and Postgres.
- Postgres tests for FTS, vector search, topic key lookup, supersession, outbox, export, and import.
- API tests for authenticated server-mode requests.
- Isolation tests proving cross-profile access is blocked.
- Retrieval parity tests against deterministic fixtures.
- Run `./gradlew test`; run the Postgres Testcontainers subset in CI once Docker is available.

## Acceptance Criteria

- Local SQLite mode remains the default and still passes all existing tests.
- Server mode starts only when explicitly configured.
- Postgres storage supports the same logical memory operations as SQLite.
- Retrieval uses Postgres FTS and pgvector behind the existing retrieval channels.
- Authenticated requests are required in server mode.
- Profile isolation is enforced by RLS or an equivalent tested mechanism.
- Local NDJSON exports can be imported and re-embedded into server storage.

## Risks And Follow-Ups

- RLS and connection pooling must be designed together so session-scoped profile state cannot leak between requests.
- Postgres vector dimensions must match the configured embedding model; mismatches need startup validation.
- Import should avoid trusting local export files blindly because server mode may be multi-user.
